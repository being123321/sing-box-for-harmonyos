# sing-box for HarmonyOS

非官方鸿蒙原生移植，界面参考 sing-box for Android。与 SagerNet 无官方关联。

- 稳定渠道：应用 **0.90.10**，上游正式内核 **1.14.4**。
- Beta 渠道：应用 **0.90.10-beta**，上游预发布内核 **1.15.0-alpha.13**。
- 渠道按上游内核区分，不能代表所有真机测试已经完成。
- 目标设备：Pura X / HarmonyOS 7.0.0.109；SDK API26，最低兼容 API22。
- 下载：[GitHub Releases](https://github.com/being123321/sing-box-for-harmonyos/releases)。HAP 未签名，需沿用原签名覆盖安装；不要卸载或清除数据。稳定版与 Beta 包名不同，分别保存数据。

## 本次更新

本次只发布最新 0.90.10，未发布的 0.90.6、0.90.7、0.90.8、0.90.9 不单独创建 Release；以下汇总自 0.90.5 公开版本以来的最终改动。

- **后台快照精简（0.90.6）**：VPN 扩展只在 UI 活动租约有效时生成 Tailscale 界面状态快照；退到后台后不再调用 `nativeCore.tailscaleStatus()`，也不再写 `tailscale-status.json`。原先快照随后台 3 秒心跳触发，理论上最多约 1200 次/小时，这是调用次数估算，不是实测耗电或内存数据。Tailscale 连接、显式命令、VPN 心跳、核心健康检查、切网和恢复策略不变。
- **透明玻璃与状态栏覆盖（0.90.7-0.90.9）**：原生沉浸材质可用时，页眉、导航和运行栏不再叠加 40% 底色和额外 12vp 背景模糊，改用 3%/6% 低透明底色；能力较低时使用 6vp 轻薄模糊后备，“减少透明效果”仍切换为实色。全宽页眉玻璃覆盖“状态栏+64vp”整个区域，内容仍位于状态栏下方；页眉不再叠加外框和阴影，避免材质断层。
- **运行栏尺寸（0.90.7-0.90.8）**：底部导航下移 6.4vp 并保留系统手势安全区；运行栏相对 0.90.7 放大 120%，约为最初尺寸的 84%，在仪表盘上以 84% 宽度显示，字号、图标、间距和圆角同步调整。取消为浮动栏缩短滚动视口和额外底部预留，内容恢复到浮动控件背后延伸。
- **节点选择卡顿优化（0.90.10）**：Clash 策略组卡片身份不再包含当前选择和全部节点延迟，选择或延迟刷新不会销毁重建整张卡片及展开网格；选中状态和延迟独立更新，相同快照不重复更新。点击后立即显示“切换中”，已有选择或正在处理时不重复提交，失败保留已确认选择且不提前显示成功。手动选择后停止派发本轮剩余自动测速请求；已在核心开始的测速不强制中断，也不重启 VPN 或内核。
- **内核与验证**：完成 v2rayH 生命周期及内核源码对照，没有复制对方实现、更换网络栈或修改内核二进制。26 项展示状态、真实选择处理、自动测速批次、节点保留及 VPN 恢复相关测试通过；两渠道 HAP 编译、身份与版本、原生库 Deflate 压缩和 ZIP 完整性检查通过。

详见 [0.90.10 更新说明](docs/releases/0.90.10.md)。实际设备帧率、选择耗时和原生材质仍需签名装机复测；本次不宣称消除所有卡顿，也不宣称彻底解决 VPN 掉线或 IPv6/WebRTC 泄漏。

## 后台快照与界面

0.90.6 起，`publishTailscaleStatus()` 先检查 UI 活动租约；前台才读取 Tailscale 状态并写入界面快照，后台直接返回。Tailscale 实际连接、显式命令、VPN 心跳、内核健康检查、切网和断线恢复策略不变；回到前台后恢复快照刷新。它减少的是后台界面状态查询和文件写入，不是 VPN 数据路径或保活机制的替代。

0.90.7-0.90.9 的运行栏以导航栏尺寸为基准：0.90.7 先缩到 70%，0.90.8 在 0.90.7 基础上放大到 120%，即最初尺寸的 84%；宽度固定为仪表盘的 84%，高度、字号、图标、间距和圆角按同一比例调整。底部导航仍保留系统手势安全区，页面内容可延伸到浮动栏背后，但不再为浮动栏预留大块空白。0.90.9 的薄烟灰玻璃只调整透明度和高光，不改变这些尺寸。

0.90.10 只改变策略组卡片的复用与提交逻辑：卡片的 key 由策略组 tag、类型、可选择性和节点结构组成，不再随选中项或延迟变化；选中项和延迟通过独立 Map 更新。手动选择与自动测速通过交互版本号协调，避免同一轮测速继续派发。该改动不改变 sing-box 内核、网络栈或配置存储。

后续所有 HAP 均保留 `entry/src/main/module.json5` 的 `compressNativeLibs: true`。构建后必须运行 `node scripts/verify-hap-compression.mjs <HAP路径>`，校验实际 ZIP 条目的原生库采用 Deflate 压缩；Windows 可使用 `scripts/build-compressed-hap.ps1` 同时构建与校验。压缩发生在签名前，不能重新打包已签名 HAP。

## 使用

工具／设置 → 基础配置 → 节点选择，可通过链接、二维码、订阅、手动表单和 sing-box JSON 导入节点；模式选择支持 GFW 与大陆以外分流。也可直接导入自己的完整 sing-box JSON。策略组选择与仪表盘直连／规则／全局模式会持久化。

按需连接命中排除 SSID 时停止代理内核并释放 TUN，优先于分应用代理；手动测速不自动恢复 VPN。完整应用列表依赖获批的 GET_BUNDLE_INFO_PRIVILEGED 签名授权，普通签名不保证枚举全部应用。

WebRTC 禁用 STUN 在规则／全局模式拦截可识别的 UDP STUN；直连模式、SSID 挂起及排除应用保留直连语义。浏览器本地候选和系统 IPv6 接管需另外验证。

## 构建与许可证

每个渠道的完整对应源码 ZIP 包含修改后的 sing-box、gVisor、OHOS Go 和 SFA 参考源码，来源及二进制哈希见 BUILD-MANIFEST.json。需要 DevEco SDK API26 和修改后的 OHOS Go 工具链；普通上游 Go 无法直接替代。core/go/go.mod 使用 third_party 相对路径。根据 BUILD-THIS-VERSION.md 配置工具路径，在 DevEco 安装依赖后构建 entry Release HAP。
