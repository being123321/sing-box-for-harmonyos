# sing-box for HarmonyOS

非官方鸿蒙原生移植，界面参考 sing-box for Android。与 SagerNet 无官方关联。

- 稳定渠道：应用 **0.90.13**，上游正式内核 **1.14.4**。
- Beta 渠道：应用 **0.90.13-beta**，上游预发布内核 **1.15.0-alpha.13**。
- 渠道按上游内核区分，不能代表所有真机测试已经完成。
- 目标设备：Pura X / HarmonyOS 7.0.0.109；SDK API26，最低兼容 API22。
- 下载：[GitHub Releases](https://github.com/being123321/sing-box-for-harmonyos/releases)。HAP 未签名，需沿用原签名覆盖安装；不要卸载或清除数据。稳定版与 Beta 包名不同，分别保存数据。

## 本次更新

本次只发布最新 0.90.13；未发布的 0.90.11、0.90.12 不单独创建 Release。以下汇总自 0.90.10 公开版本以来的最终改动。

- **VPN 前台恢复（0.90.11）**：运行状态意外停止不再把用户的连接意愿改成关闭；重新进入前台后同时检查失效的运行会话和已清理的停止会话。自动恢复发送的停止命令带 `foreground-recovery` 来源标记，失败后仍可再次检查；用户主动停止仍禁止自动重连。已确认同会话内核/TUN 清理但系统扩展已退出时，需连续完整网络清单确认无 VPN 才完成停止确认；未知或仍存在 VPN 时失败关闭。
- **底部内容避让（0.90.11）**：仪表盘、配置等滚动内容按悬浮控件实际高度增加末尾空间，最后一项可以滚动到导航栏和运行栏上方，不再被底部导航遮挡。
- **模式与 Clash 节点即时高亮（0.90.13）**：直连、规则、全局点击后立即选中，不等内核命令确认，也不锁定整个界面；Clash 策略组节点点击后立即高亮。命令在后台串行提交，同一策略组连续点击会合并尚未发送的中间选择，优先最后一次。旧快照、旧回报不能覆盖较新的选择；成功后等待采样时间晚于确认时间的快照再交回实际状态，最新命令失败时提示并回退到最后已确认选择。
- **导航立即切页（0.90.13）**：导航点击或滑动松手立即切页，取消 0.90.12 的 160ms 等待；只把滚动位置重置和数据轮询延后到异步任务，既有图标/文字动画保留。
- **验证与安装**：39 项相关测试通过，包括即时高亮、连续点击合并、旧快照隔离、旧请求失败不覆盖新选择、失败回退、会话重置、导航即时切换、VPN 恢复和 Tailscale 队列。两版 HAP 构建成功，原生库内部 Deflate 压缩校验通过。

详见 [0.90.13 更新说明](docs/releases/0.90.13.md)。新版切换流畅度尚未做真机验证，长期后台稳定性也未确认；系统终止整个扩展进程仍可能导致掉线，不宣称彻底解决 VPN 断线或 IPv6/WebRTC 泄漏。

## 后台、恢复与底部避让

0.90.11 起，VPN 运行状态停止只代表运行时状态，不再等同于用户主动关闭；重新进入前台后，如果持久化的连接意愿仍为开启，会同时检查失效运行会话和已清理停止会话，并在安全条件满足时重建 VPN。自动恢复专用的停止命令不会被后续恢复误认为用户停止；手动停止、SSID 挂起和其他 VPN 不抢占等优先级不变。系统已经清除整个扩展时，扩展内定时器无法自行运行，因此该修复只保证前台恢复，不承诺后台自启动。

滚动内容末尾预留的高度取悬浮控件实际高度，运行栏显示或隐藏时都会给最后一项留出空间。该处理针对仪表盘、配置等滚动页；不能据此声称所有子页面和所有字体缩放下都逐一验证。

0.90.6 的后台 Tailscale 界面快照精简、0.90.7-0.90.9 的透明玻璃、状态栏覆盖和运行栏尺寸、0.90.10 的策略组卡片复用仍保留。详见 [0.90.10 更新说明](docs/releases/0.90.10.md)。

## 即时切换

模式和 Clash 节点选择采用“先显示、后提交”：点击后立即更新高亮，后台按选择器串行发送命令；同一选择器连续点击时合并未发送的中间值，只保留最后一次。旧快照和旧命令回报不能覆盖较新的本地选择，最新命令失败时给出提示并回退到最后确认值。停止 VPN 或 VPN 会话变化后会清空旧选择队列，丢弃迟到回报。

导航不再等待 160ms 动画后再切页；页面选择立即生效，滚动复位和状态轮询放到异步任务。ArkUI 页面仍在 UI 线程创建，异步请求不等于把页面渲染搬到后台线程。

后续所有 HAP 均保留 `entry/src/main/module.json5` 的 `compressNativeLibs: true`。构建后必须运行 `node scripts/verify-hap-compression.mjs <HAP路径>`，校验实际 ZIP 条目的原生库采用 Deflate 压缩；Windows 可使用 `scripts/build-compressed-hap.ps1` 同时构建与校验。压缩发生在签名前，不能重新打包已签名 HAP。

## 使用

工具／设置 → 基础配置 → 节点选择，可通过链接、二维码、订阅、手动表单和 sing-box JSON 导入节点；模式选择支持 GFW 与大陆以外分流。也可直接导入自己的完整 sing-box JSON。策略组选择与仪表盘直连／规则／全局模式会持久化。

按需连接命中排除 SSID 时停止代理内核并释放 TUN，优先于分应用代理；手动测速不自动恢复 VPN。完整应用列表依赖获批的 GET_BUNDLE_INFO_PRIVILEGED 签名授权，普通签名不保证枚举全部应用。

WebRTC 禁用 STUN 在规则／全局模式拦截可识别的 UDP STUN；直连模式、SSID 挂起及排除应用保留直连语义。浏览器本地候选和系统 IPv6 接管需另外验证。

## 构建与许可证

每个渠道的完整对应源码 ZIP 包含修改后的 sing-box、gVisor、OHOS Go 和 SFA 参考源码，来源及二进制哈希见 BUILD-MANIFEST.json。需要 DevEco SDK API26 和修改后的 OHOS Go 工具链；普通上游 Go 无法直接替代。core/go/go.mod 使用 third_party 相对路径。根据 BUILD-THIS-VERSION.md 配置工具路径，在 DevEco 安装依赖后构建 entry Release HAP。
