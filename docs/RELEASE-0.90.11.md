# 0.90.11

## 修复

- 意外停止 VPN 不再把用户的连接意愿改为关闭；重新进入前台后，同时检查失效运行会话和已经清理的停止会话。
- 自动恢复发送的停止命令带有来源标记，失败后允许再次检查；用户主动停止仍禁止自动重连。
- 已取得同会话内核/TUN 清理确认，但系统扩展已经退出时，只有连续完整网络清单确认没有 VPN，才允许完成停止确认。未确认清理的陈旧运行会话仍需要原有系统停止、VPN 消失和文件锁校验。
- VPN 状态轮询只读取 Tailscale 缓存，不等待最长 15 秒的端点命令响应。
- 心跳不可确认时不继续把缓存状态标记为健康连接；正常系统日志记录前台恢复失败原因，不增加 VPN 运行监控页面。
- 仪表盘、配置等滚动内容增加与悬浮控件高度对应的末尾滚动余量，最后一项可以滚动到导航栏和启动栏上方。

## 构建和验证

- 稳定内核 1.14.4；Beta 内核 1.15.0-alpha.13。本次未替换原生内核。
- 版本代码 1000120；保留原包名和存储标识，使用原签名覆盖安装，勿卸载或清除数据。
- 两个 HAP 均构建成功，原生库内部 Deflate 压缩验证通过，约 25.5 / 26.2 MiB。
- 63 项相关回归通过，覆盖前台恢复、连接意愿、手动停止、网络恢复、系统状态未知/其他 VPN、协议安全门、Tailscale 队列及缓存、策略组和保留节点。未声明完整历史测试集全部通过。
- 真机故障现场已读取；修复包尚待原 HoKit 签名覆盖安装后的真机回归，不保证系统不再销毁 VPN。

## 本次现场与边界

手机安装 0.90.10 Beta。2026-11-06 23:57:59 VPN 启动成功；23:58:20 系统最近任务日志记录移除应用任务卡片，随后 UI 进程退出，NetworkVpnManager 收到该进程死亡并销毁虚拟网络，VPN 扩展进入销毁回调；23:58:22 新 UI 进程启动。随后多次查询均无 VPN 扩展进程、无 vpn-tun，但界面仍显示“已启动”。这次有任务移除及调用进程退出的证据，不能归因为旧现场的 SwapFull，也不能据此解释所有历史掉线。

恢复代码存在三类缺口：正常返回的停止状态会清除连接意愿；自动恢复首次发送停止后失败，其命令会被后续恢复误认作主动关闭；前台恢复只处理部分陈旧运行状态。另有可选端点查询阻塞主状态轮询的风险。本次针对这些路径修复，保留系统状态未知时不抢占 VPN 的边界。

系统已经停止整个扩展时，扩展内定时器无法自行运行。本次提供前台恢复修复，不承诺在进程已被系统清除后仍可后台自启动。
