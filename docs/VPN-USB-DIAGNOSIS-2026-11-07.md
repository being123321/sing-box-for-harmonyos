## 结论与限制

当前现象是扩展进程被终止后系统移除 VPN；0.90.11 引入的前台恢复仍有效。它只能在 UI 再次运行时处理孤立会话，不能让已死亡扩展中的定时器继续执行。

时间上，IPv6 网络重建发生在扩展死亡前约 6 秒，低内存区域事件与进程死亡几乎同时发生。这是继续调查网络重建的分配峰值和系统内存回收的重要线索，但不能据此认定 OOM、配置错误、节点故障或用户主动关闭。InvalidKillId 不等于可解读的具体终止原因。

普通调试权限下 dmesg 和 faultlog/hiview 历史目录不可读，hisysevent 查询未返回事件。可读的落盘 hilog 为厂商压缩记录：记录头的时间与 PID 可提取，部分系统消息仅有格式索引和参数。不得把尚未还原的格式索引猜成明确的终止原因。

不能为消除重建而直接移除 IPv6 路由保护：该路径用于既有切网泄漏问题。在没有等效路由验证前，不应以泄漏风险换取表面不断线。也没有通过调试写入进程回收评分、开启隐藏持锁或修改系统回收策略。

原始日志、落盘压缩日志、布局及内存采样保留在工程外 work 的 vpn-usb-*private* 文件中，仅供本地排查，不随源码或 Release 上传。未因这次诊断替换手机安装包，也未宣称长期后台掉线已解决。
